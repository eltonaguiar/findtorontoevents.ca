1. What CSM is

Keep one sentence in your head: CSM is external service management — who the customer is, what they own, what they are allowed to receive, how they reach you, and how work is fulfilled.

The Certified Implementation Specialist – Customer Service Management exam confirms you have the knowledge and skills to configure, implement, and maintain the ServiceNow CSM application. This certification validates their ability to manage data models, configure case routing, oversee case processes, and utilize CSM workspaces, portals, and analytics.
ServiceNow CIS-CSM exam blueprint, KB0011529 (updated November 2025)
ServiceNow's Customer Service Management (CSM) application is a way for service providers to manage relationships between themselves and the customers who use and/or purchase their services and products.
ServiceNow Community — CSM Fundamentals
The process itself should not be confused with an application designed to help manage and improve the process. The latter is where ServiceNow's Customer Service Management application plays a part.
Same article — process vs product
CSM provides an end-to-end service management solution with an integrated problem, change, configuration, work order management, and a structured service catalog. It helps break down the classic silos … by connecting customer service with engineering, field service, finance, and other teams.
Same article — why CSM is not a standalone ticketing app
Customer service is all about providing services to customers before, during, and after the purchase of a product and/or service.
Why the data model includes products, install base, and entitlements
Customers reach out to customer service support to report an issue or problem, ask a question, make a request or complaint … in relation to products they have purchased. Customer service support is responsible for streamlining customer interactions while acting as the intermediary between the customer and the service operations teams.
Intake → case → fulfillment

3. Domain 1 — Foundational data model (27%)

Blueprint: business models, product models, install base, contracts and entitlements.

Business-to-business (B2B) is a business model where commercial transactions are conducted between two or more companies. Business-to-consumer (B2C) is a business model where companies sell products and or services directly to consumers.
CSM Fundamentals
Foundation data includes all of the data crucial to support customers as efficiently as possible. Most of the foundation data can be imported and configured using Customer Service Management Guided Setup.

Account [customer_account] extends the Core Company [core_company] table. An account can have one or more associated cases, contacts, assets, service contracts, entitlements, relationships.
An external account can have multiple contacts, but a contact can be associated with only one account. Contact [customer_contact] extends the User [sys_user] table.

Contact relationships are the exception path that lets a contact work across related accounts. Accounts and consumers can have multiple addresses but only one primary address.

Hierarchy vs relationship

  • Account hierarchy: Parent Account field. Parent–subsidiary. A customer admin (sn_customerservice.customer_admin) can see subsidiary assets/users and create/view cases for subsidiaries on the portal.
  • Account relationship: Explicit From → To record, based on a relationship type (partner-to-account or account-to-account).
  • Partner: Sells to and supports customers; can report/manage cases on behalf of customers; can also be a customer.

Official sample: an account relationship record includes Account From and Account To.

Product → install base → entitlement → case

Product model (what you sell) → Sold product (what this customer bought) → Install base item (provisioned instance) → Contract / entitlement (allowed support) → Case (work, with entitlement attached).

Sold products are products and components that have been sold to an account or a consumer and can have multiple contracts. An install base item is an instance of sold product that has been provisioned for an account or consumer.
ServiceNow docs
Entitlement checks occur as part of post-sales support … to determine what services customers are eligible to receive for the products they've purchased.

Zurich: sn_customerservice.advanced_entitlements — true = multiple entitlements on a case (related list); false = single Entitlement field.

4. Domain 2 — CSM configuration (38%)

Heaviest domain. Blueprint: CSM in ServiceNow, routing and assignment, case types, channels.

While they share the same core requirements such as accounts, contacts, partners, contracts, entitlements, each industry type also has specific needs … by creating industry-specific data models … In addition, case types can be created that are more suited to that particular industry.
  • Customers arrive on a channel. That often creates an Interaction. Lookup and Verify identifies the person. Then a Case is created.
  • Typical channels: email, chat, walk-up, telephony, portal/catalog, virtual agent, engagement messenger.
  • Advanced Work Assignment (AWA) routes work using service channels, queues, assignment rules, capacity, and skills.
  • Official sample: AWA service channels used by CSM include Walk-up, Chat, and Case.
  • Case type: specialized case with its own form, process, playbook, often a table extension.
  • Service definition: ties catalog / portal / case type so intake is consistent.
  • Prefer configuration (case types, playbooks, AWA, assignment rules) over custom code.

5. Domain 3 — Case management (17%)

Blueprint: state flows, major issue management, case digests and service definitions, CSM workspace, case actions / tasks / escalations.

Official sample: the final state of a case is Closed (not Resolved).

Typical flow to explain: New → Open → Awaiting Info / Work in Progress → Resolved → (customer accepts) → Closed.

Major issue management is CSM’s cousin of Major Incident: one parent issue, many affected customers, child/related cases, case digest / communications, often knowledge + targeted communications.

A great thing about CSM is that it can be easily integrated with other ServiceNow products … It can link a case to an incident, problem, change, or request. Another great example is its integration with FSM for on-site support … by creating a work order.

10. Hands-on PDI checklist

  1. Activate CSM (+ install base / contracts if needed) and open Guided Setup.
  2. Create a parent account, child account, contacts, account relationship, partner.
  3. Create a consumer and register via Consumer Service Portal.
  4. Create a product model, sold product, install base item.
  5. Create a contract and entitlement; open a case and attach entitlement.
  6. Create two case types and a service definition / catalog record producer.
  7. Stand up AWA for Case and Chat; watch a case land in a queue.
  8. Walk a case New → … → Closed; add a task and an escalation.
  9. Create a special handling note and an SLA.
  10. Publish a knowledge article with a knowledge block and find it on the portal.
  11. Open CSM Configurable Workspace and resolve the same case from there.

11. When code actually matters

CIS-CSM is not CAD. You will not pass by memorizing GlideAjax. Code shows up in real projects as entitlement lookups, GlideQuery helpers, or REST to a billing/product system.

Use servicenow_scriptincludesample after this page: GlideQuery vs GlideRecord vs GlideAggregate, GlideAjax (AbstractAjaxProcessor, return a string), gs / GlideUser, RESTMessageV2.

Rule: configure first (case type, AWA, playbook, assignment, portal). Script only when the data model and process cannot express the rule.
